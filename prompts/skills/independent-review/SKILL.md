# 독립 검수 프로토콜 (independent-review)

자신이 작성하거나 구현한 결과물은 같은 맥락이나 포크된 맥락에서 공정하게 검증할 수 없다.
계획·설계·코드 산출물을 확정하거나 완료 선언하기 전 반드시 이 절차로 편향 없는 검증을 수행한다.

## 핵심 원칙: 단절된 새 컨텍스트

- **항상 새 컨텍스트 사용**: 작성자 대화의 연속이나 포크를 사용하지 않는다. 제작 과정의 변명·시행착오·설득 서사가 전혀 없는 새 독립 에이전트를 기동한다(또는 별도 유휴 Herdr 탭에 `relay_send`로 전달).
- **역할 코어 로드**: 검수 에이전트에 `cortex_prompt(kind: "agent", name: "reviewer")`를 명시 로드한다. 코드·아키텍처·테스트 검수라면 `cortex_prompt(kind: "standard", name: "DEVELOPMENT_STANDARD")`도 함께 로드한다.

## 1단계: 1차 근거 전용 브리프 구성

검수 에이전트에 전달하는 브리프에는 **작성자의 자기 합리화나 결론 유도 문구를 배제**하고 오직 1차 근거만 담는다.

1. **원래 목표 기준선 (`P0` 또는 합의 계약)**: `memory_read`로 직접 읽을 기준선 ID와 핵심 요구사항.
2. **확정된 결정 및 경계**: `memory_search` / `memory_read` 대상 결정 문서 ID, 수정 허용 범위, 유지해야 할 외부 계약.
3. **실제 산출물 위치**: 변경된 파일 목록, 실제 diff, 또는 검토 대상 계획 문서 ID.
4. **실제 실행 근거**: 실행한 검증 명령과 관측된 원문 출력(테스트 결과, E2E 실행 로그).

## 2단계: 독립 검수 실행 및 구조화 판정 형식

검수 에이전트는 코드를 직접 수정하지 않고 1차 근거를 직접 읽어 `reviewer` 역할 코어와 동일한 아래 5개 구획으로 결과를 반환한다.

- **Verified Facts (확인된 사실)**: 직접 읽은 파일·라인·기준선 ID·실행 출력으로 확인된 사실.
- **Open Facts (미결 사실)**: 제공된 1차 근거만으로 확인되지 않아 추가 확인이 필요한 지점(없으면 `없음`).
- **Blockers (필수 수정)**: 원래 목표(`P0`) 또는 확정 계약 위반, 누락된 요구사항, 실제 실행 실패, 안전·경계 위반. 각 항목은 근거 위치와 재현/영향을 명시한다(없으면 `없음`).
- **Minor Notes (참고 사항)**: 차단은 아니지만 인지할 가치가 있는 경미한 관찰. 억지로 채우지 않는다(없으면 `없음`).
- **Verdict (판정: `ACCEPT` | `NEEDS_FIX`)**:
  - `ACCEPT`: 차단 결함 없음. 발견 사항이 0건이면 `ACCEPT (Clean Evaluation)`을 정상 결과로 보고한다.
  - `NEEDS_FIX`: 1건 이상의 차단 결함이 존재함.

## 3단계: HEAD 최종 판정 및 후속 처리

최종 수용·보완 결정 권한은 리뷰어가 아니라 **원래 사용자 합의를 소유한 HEAD**에 있다.

- HEAD는 리뷰어의 `Verified Facts`, `Open Facts`, `Blockers`를 원래 사용자 합의와 대조해 타당성을 판정하고, 최종 판정에 영향을 주는 `Open Facts`가 있다면 직접 1차 근거로 확인한 뒤 결정한다.
- `ACCEPT` 확정 시 HEAD가 정본 기억(`memory_save`/`memory_update`)을 갱신하고 다음 단계로 진행한다.
- `NEEDS_FIX` 확정 시 수정은 별도 작업 컨텍스트(직접 수정 또는 `delegate`)에서 수행하고, 수정 완료 후 재검수는 **이전 리뷰 컨텍스트를 재사용하지 않고 새로운 독립 컨텍스트**에서 다시 수행한다.
