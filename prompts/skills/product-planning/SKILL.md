# 제품 기획 (product-planning)

기능이나 제품의 방향이 아직 구체화되지 않았을 때 저·중해상도에서 기획을 구조화하는 3단계 절차다.
구현 기술이나 코드 구조로 내려가기 전에 아래 3단계를 순서대로 통과하며 각 단계 결과를 사용자와 확인한다.

## 사전 확인

- `memory_overview`와 `memory_search`로 기존 제품 결정·제약·사용자 선호를 먼저 확인한다.
- 기존 결정과 충돌하는 방향이 나오면 숨기지 않고 변경 필요성과 영향을 명시한다.

## 1단계: 문제 정의

- **대상 사용자와 상황**: 누가, 어떤 맥락에서, 무엇 때문에 막히거나 비용을 치르는지 사실 기준으로 서술한다.
- **현재 대안의 한계**: 기존 방식이 실패하거나 불충분한 지점을 구체적으로 짚는다.
- **해결 범위와 비범위**: 이번 기획이 해결할 핵심 문제와 의도적으로 다루지 않을 문제를 구분한다.
- **성공 신호**: 문제가 실제로 해소되었음을 외부에서 관측할 수 있는 기준을 정의한다.

## 2단계: 사용자 가치

- **핵심 가치 제안**: 사용자가 얻는 구체적 결과(시간 절감, 오류 방지, 판단 단순화 등)를 1~3개 문장으로 압축한다.
- **가치 성립 조건**: 그 가치가 체감되기 위해 반드시 유지되어야 할 품질·신뢰·지연·정확도 조건을 명시한다.
- **트레이드오프**: 핵심 가치를 얻기 위해 포기하거나 단순화하는 요소를 명시해 범위 확장을 막는다.

## 3단계: 유저플로우 (자동화 vs 사용자 통제 분리)

사용자의 시작 시점부터 목표 달성까지 주요 흐름을 단계별로 기술하되, 모든 단계에서 **시스템 담당**과 **사용자 통제 지점**을 명시적으로 분리한다.

| 플로우 단계 | 시스템 자동 처리 (저마찰·자동화) | 사용자 통제 지점 (확인·선택·개입) | 실패·예외 시 복구 경로 |
| :--- | :--- | :--- | :--- |
| 진입 / 트리거 | 기본 상태 수집·맥락 복원 | 목표·범위 시작 확인 | 입력 부족 시 최소 질문 |
| 핵심 실행 | 반복·계산·검증 자동 수행 | 되돌리기 어려운 변경 전 승인 | 실패 원인 노출 및 안전 중단 |
| 결과 확인 | 핵심 결과와 근거 요약 제공 | 최종 수용·수정·취소 결정 | 이전 기준선으로 복귀 |

- 되돌리기 어렵거나 외부 상태를 바꾸는 지점은 반드시 **사용자 통제 지점**으로 배치한다.
- 반복적이고 가역적인 준비·조회·정리 작업은 **시스템 자동 처리**에 두어 사용자 인지 부하를 줄인다.

## 산출물 고정 및 다음 단계 연결

- 3단계 합의가 끝나면 HEAD가 `memory_save`로 기획 정본(`type: "baseline"` 또는 `type: "decision"`, 기존 기획 대체 시 `supersedes` 지정)을 저장한다.
- 구현으로 넘어갈 때는 `HEAD_CORE`의 규모 판정(S/L)을 따르며, L 작업이면 `start-job` 절차에 따라 단일 경계 작업은 `delegate`로, 다단계 계획·검수·실행이 필요하면 `plan-run`의 `P0` 기준선으로 연결한다.
